## Correction to finding B (added 2026-07-25, later same day)

Finding B was verified by building the arm64 image locally and loading the real
S3 artifacts inside it. Both parts of the original diagnosis were wrong:

1. **There was no pickle mismatch.** `artifacts.pkl` references the numpy 1.x
   `numpy.core.multiarray` namespace, so it was produced under numpy 1, matching
   what Lambda already ran. It also loads fine under numpy 2.x via the
   `numpy.core` compatibility shim, so neither direction was broken.
2. **The fix made the image unbuildable.** `catboost==1.2.7` requires
   `numpy<2.0`, so `numpy==2.1.2` makes `requirements-lambda.txt` unresolvable
   and `docker build` fails with pip `ResolutionImpossible`. Production was
   spared only because the live Lambda image dates to 2026-06-11, before the
   change. The next deploy would have failed.

`backend/requirements-ml.txt` carried the same impossible `numpy==2.1.2` +
`catboost==1.2.7` combination. It had gone unnoticed because nobody had ever
resolved that file: the local venv has neither catboost nor xgboost installed.

Both files are now pinned to `numpy==1.26.4`. Verified end to end inside the
image that ships:

```
numpy 1.26.4 · sklearn 1.5.2 · catboost 1.2.7 · lightgbm 4.5.0   (resolve, build exit 0)
RAW PICKLE LOAD: OK (20 keys, n_folds=5, meta_learner=LogisticRegression)
SKLEARN ROUNDTRIP: OK  scaler.transform(1,816) -> mlp.predict_proba(1,5)
APP LOADER triage_ml._load(): OK  keys=26  lgbm_folds=5
```

**Process note:** the auditors first scanned `main`, and finding B was accepted
without building the image. Any dependency-pin finding should be validated by an
actual resolve or build before it is called a fix.

## CodeBuild pipeline drift (found 2026-07-25)

The CodeBuild project `solace-api-deploy` does **not** build this repo:

- Source is `github.com/Dhruvjain35/solace-ai` (upstream original), `sourceVersion`
  null, so it builds that repo's default branch.
- It carries its own **inline** buildspec, so the `buildspec.yml` in this repo is
  not what runs.

So triggering a build today would deploy upstream `main` to the live Lambda, not
the work on this branch, and edits to `buildspec.yml` have no effect until the
project is repointed. `buildspec.yml` has been corrected anyway (account ID
derived via STS, `--platform=linux/arm64`, BOM stripped, explicit `--region`) so
it is right whenever the project is switched over.

Also corrected: the audit listed the missing `--platform=linux/arm64` as a risk.
The Lambda is `arm64` and the CodeBuild environment is `ARM_CONTAINER` on
`amazonlinux2-aarch64-standard:3.0`, so the native build already produced arm64.
The flag is hygiene for non-CodeBuild hosts, not a live defect.

## Not fixed (deliberate — flagged for follow-up)

- ~~**`any` typing (QUAL-007)**~~ **DONE.** 90 type-level `any` reduced to 0; the 44
  remaining are `catch (e: any)`, which this finding scoped out. Response types
  were derived from the backend service behind each endpoint rather than blanket
  cast. The pass exposed four real defects `any` had been hiding: the sepsis EWS
  api cast omitted `calibration_note`, which the backend does return;
  `coding.cpt_procedures` and `coding.modifiers` were guarded with
  `(x || []).length > 0` but then indexed as `x.map(...)`, so the narrowing never
  applied at the use site; and `discharge.red_flags?.length > 0` compared
  `undefined` to a number and only behaved correctly by accident.
- **Local venv does not match the pins.** It has numpy 2.4.4, pandas 3.0.2 and
  scipy 1.17.1 against pinned 1.26.4 / 2.2.3 / 1.13.1. Deliberately left alone:
  pandas 3.0.x wheels are built against the numpy 2.x ABI, so downgrading numpy
  on its own risks breaking a green 743-test suite for no gain, since the Lambda
  image is what ships and was verified separately. Full alignment means
  reinstalling the ML stack.
- **Patient result i18n is model-authored.** USAB-008 is fixed (26 keys across
  all 20 languages, routed through `t()`), but the non-English clinical copy is
  unreviewed. The ESI strings tell a patient how urgent their condition is, so
  they want native and clinical review before production reliance.
- **The pre-load spinner on the result screen stays English**, because it renders
  before the patient's language is known.
- **CCPA delete/export** (COMP-010) still unwired; **provenance override log** is
  now DDB-backed on this branch but confirm the S3 6-year archive path.
- **Account ID in docs** was scrubbed to `<AWS_ACCOUNT_ID>`; the KMS key UUID in
  `scripts/iam_solace_developer_policy.json` is still literal.
